# INMISE — кабинет артиста

Ванильный JS без фреймворка: `admin/index.html`, `scripts/artist-terminal.js`,
`styles/artist-terminal.css`. Данные — Supabase. Деплой — загрузка файлов на reg.ru.
Локально: `npm run dev` → `localhost:3000/admin/`.

Общение — по-русски, коротко, по пунктам. Владелец мало читает длинный текст.

## Как выглядит хорошо

- Не заключать блоки в рамки. Не делить экран полосками.
- Телефон равноправен ноуту — половина заходов с него. Каждый экран проверять на узкой ширине.
- Одна вещь показывается один раз. Если факт виден в трёх местах — два лишние.
- Заголовки вроде «План релизов / Календарь» над очевидным — убирать.
- Цвет только там, где он что-то значит: просрочено — красный, ожидание — янтарный.
  Зелёный не должен гореть, когда всё плохо.
- Наезды подписей недопустимы. Раскладывать по сетке, а не абсолютным позиционированием.

## Как ведёт себя система

- Система не решает за артиста — спрашивает. Просроченный этап получает
  «сделал / перенести», а не приговор «пропущено».
- Ничего не переписывать молча при открытии окна. Массовые изменения — только
  по явному действию с подтверждением, где названы числа.

## Как работать с кодом

- После любой правки JS или CSS бампать `?v=` в `admin/index.html` у обоих файлов.
- `node --check` проверяет только синтаксис. После вырезания кода сверять список
  функций с `git show HEAD:…` — однажды снёс `bindStageButtons` и кабинет не открылся.
- Вырезать по границам содержимого с ассертом, не по номерам строк — строки уезжают.
- Геометрию проверять на настоящем CSS проекта, не на самодельных стилях.
- Кнопка внутри кнопки — невалидная разметка, браузер её разбирает и ломает структуру.
- Коммит только по просьбе. Коммит-сообщение по-русски, с причиной, не только с фактом.
- Ветки `DDMMYYYY_release`. В коммит не тянуть чужие untracked-файлы
  (`assets/brand/`, `output/`, `tools/*`).
